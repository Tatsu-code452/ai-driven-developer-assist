# タスク管理設計書

## 1. 目的・適用範囲

SCR-021の一覧とSCR-022の詳細で、Taskの検索・絞り込み、登録、参照、更新、状態変更を行う。画面遷移、未登録ID、読込失敗、未保存変更の共通方針はTSK-005の承認済み設計に従う。

本書で既存要件にない操作や初期値を定める箇所は、実装可能なMVPの設計判断であり、未承認の業務要件を確定したものではない。

## 2. Taskデータ

| 項目 | 登録・更新規則 |
|---|---|
| `id` | サーバーが発行し、利用者は変更できない。 |
| `title` | 必須。前後の空白を除去し、200文字以内で保存する。 |
| `description` | 任意。 |
| `status` | `TODO`、`DOING`、`DONE`のみ。新規登録は`TODO`。 |
| `priority` | `LOW`、`NORMAL`、`HIGH`のみ。初期値は`NORMAL`。 |
| `source` | 新規登録は`手動登録`を自動設定し、編集不可。既存値は更新で保持する。 |
| `projectId` | 既存データでは任意。新規登録と更新では必須。プロジェクト一覧の選択肢から指定する。 |

既存データにProjectとの関連がない場合は未割当のまま表示する。関連先を推測して初期プロジェクトへ割り当てない。未割当の既存Taskは、詳細の編集時に利用者がProjectを選択して関連付ける。

### ID採番

- IDは3文字の`TSK` PREFIXと3桁連番を使う。
- WBS-001には計画タスク`TSK-001`〜`TSK-030`が登録されているため、新規管理Taskはその範囲を予約し、`TSK-031`以降を発行する。既存の生成データだけを見て`TSK-009`から採番しない。
- TSK-009で予定されている中央採番との連携は本タスクの範囲外。既存データ中のID重複を変更・修復せず、中央採番の正式方針が確定した後に扱う。

## 3. SCR-021 タスク一覧

- キーワード（IDまたはタイトル）、Project、状態、優先度で絞り込む。初期表示は全件。Project条件には「プロジェクト未設定」を含める。
- ID昇順で表示し、1ページ20件とする。検索条件とページはURLクエリに保持し、条件変更時は1ページ目に戻す。
- 検索・絞り込み・ページングはサーバー側で適用し、該当件数とページ情報を返す。範囲外の正のページ番号は最終ページに丸め、不正な値は400とする。
- 「新規タスク」でSCR-022の作成モードを開く。ID選択で対象のSCR-022を開く。詳細から戻る際は検索条件とページを復元する。
- Projectの詳細に表示される関連Task件数から、同じProjectで絞り込んだSCR-021へ移動できる。

## 4. SCR-022 タスク詳細

- `id`指定時は参照モード、`mode=edit`は編集モード、`mode=create`は新規作成モードとする。
- ID、タイトル、説明、Project、状態、優先度、出典を表示する。IDと出典は読み取り専用。
- タイトルは必須、説明は任意。新規作成ではProjectを必須選択し、状態は`TODO`、優先度は`NORMAL`を初期値とする。
- 状態遷移は`TODO → DOING`、`DOING → DONE`、`DONE → DOING`を許可する。同じ状態の保存も可能。状態変更は保存操作でのみ反映する。
- 更新成功後は参照モードへ戻る。既存TaskのIDと出典は保持する。
- 一覧へ戻る・編集を取り消す際、未保存変更があれば破棄確認を行う。詳細を直接開いた場合の戻り先は安全なSCR-021 URLに限定する。

## 5. API・永続化

Taskは既存の`backend/data/generated/tasks.json`に保存する。既存の生成データ保存形式を維持し、レコードの置換・追記は同期ファイル操作で行う。

| 操作 | API | 挙動 |
|---|---|---|
| 一覧 | `GET /api/tasks?q=&projectId=&status=&priority=&page=` | ID昇順の絞り込み済みページと総件数を返す。`projectId=unassigned`は未割当だけを返す。 |
| 参照 | `GET /api/tasks/:id` | 指定Taskを返す。未登録は404。 |
| 登録 | `POST /api/tasks` | 必須Project、タイトル、状態、優先度を検証し、サーバー側でIDと出典を設定する。新規状態は`TODO`に限定する。 |
| 更新 | `PUT /api/tasks/:id` | タイトル、説明、Project、状態、優先度を更新する。IDと出典は変更しない。 |

Project IDは`PRJ-###`形式を検証し、画面では`GET /api/projects`の結果から選択する。中央採番・Project永続化との一体化は本タスクでは行わない。

## 6. エラー扱い

- 不正な絞り込み、ページ、入力、状態遷移は400を返し、成功応答に置き換えない。
- 未登録Task IDは404。読込・保存エラーは既存エラーハンドラーに渡す。
- フロントエンドは一覧・詳細の読込エラーを明示し、再試行と一覧へ戻る操作を提供する。保存失敗時は入力内容を保持する。
- 空の絞り込み結果は「該当するデータがありません」と表示する。
- 存在しないProjectへの参照整合性検証と全成果物間の一意なID採番は、Project永続化および中央採番の後続設計で扱う。

## 7. 未確定事項

- 中央採番サービスとの連携、および既存の計画IDと生成Task IDの重複を解消する移行方針。
- Project IDの存在確認をTask APIとProject永続化の間で一元化する方法。
