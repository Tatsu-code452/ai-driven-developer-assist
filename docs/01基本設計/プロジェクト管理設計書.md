# プロジェクト管理設計書

## 1. 目的・適用範囲

SCR-002 プロジェクト一覧とSCR-003 プロジェクト詳細でプロジェクトを登録・参照・更新し、明示的にプロジェクトへ関連付けられたタスクと成果物の件数を追跡する。画面遷移・検索・ページングの共通方針はTSK-005でレビュー承認された設計を前提とする。

本書で既存要件にない操作や初期値を定める箇所は、実装可能なMVPの設計判断であり、未承認の業務要件を確定したものではない。

## 2. 管理データ

| 項目 | 型 | 登録・更新規則 |
|---|---|---|
| id | String | システムが`PRJ`採番で発行。利用者は変更不可。 |
| name | String | 必須。前後の空白を除去して保存する。 |
| description | String | 任意。 |
| status | String | 任意。既存の値をそのまま保持し、固定の状態一覧を強制しない。 |
| rootPath | String | 任意。プロジェクトの管理データ(`docs/99管理`等)のフォルダーパス。未設定は空文字。バックエンドを実行する環境から参照できるパスを指定する。 |
| taskCount | Number | 保存しない集計値。`projectId`が一致するタスク数。 |
| documentCount | Number | 保存しない集計値。`projectId`が一致する成果物数。 |

最初のデータファイルが存在しない場合は、既存画面が表示していた`PRJ-001`（AI駆動型開発支援システム、進行中）を初期プロジェクトとして扱う。初回更新時に初期データを含めて永続化する。既存タスク・成果物にプロジェクトIDがない場合は関連を推測せず、どのプロジェクトの集計にも含めない。

## 3. SCR-002 プロジェクト一覧

- ID・プロジェクト名のキーワード検索と状態の部分一致検索を提供する。初期値は全件表示。
- プロジェクト名昇順、同名の場合はID昇順にする。
- 1ページ20件。検索語・状態・ページをURLクエリに保持し、条件変更時は1ページ目に戻す。
- 一覧項目はID、名称、状態、関連タスク数、関連成果物数とする。名前またはIDを選ぶとSCR-003の参照モードへ移動する。
- 「新規プロジェクト」はSCR-003の作成モードへ移動する。

## 4. SCR-003 プロジェクト詳細

- `id`ありは参照モード、`mode=create`は新規作成、編集操作後は編集モードとする。
- ID、名称、説明、状態、関連タスク数、関連成果物数を表示する。作成・編集フォームは名称、説明、状態を編集し、IDと集計値は読み取り専用。
- 保存成功後は参照モードに戻る。入力不備は400、ID未登録は404、読込・保存エラーは明示し、入力内容を保持する。
- キャンセル・一覧復帰で未保存変更があれば、破棄確認を行う。一覧へ戻る際は元のURLクエリを復元する。
- Projectの状態語彙は要件で定義されていないため、自由入力の文字列として保持する。既存値を別の状態へ暗黙変換しない。
- 参照モードでは、`rootPath`直下の`README.md`にある「管理データ一覧」見出し配下の箇条書きリンクを「管理データ一覧」として表示する。各項目は名称、`rootPath`からの相対パス、ファイルの有無(あり／ファイルなし)とする。リンク先ファイルの内容はこの画面では表示しない。
- `rootPath`未設定、フォルダーなし、`README.md`なし、見出しなしの場合は、空の一覧として扱わず、原因を示すメッセージを表示する。読込エラーは再試行操作を表示する。

## 5. API・永続化

| 操作 | API | 挙動 |
|---|---|---|
| 一覧 | `GET /api/projects?q=&status=&page=` | 検索・並び順・ページング済み一覧、総件数、ページ情報を返す。 |
| 参照 | `GET /api/projects/:id` | 指定Projectと関連件数を返す。未登録は404。 |
| 登録 | `POST /api/projects` | 名称、説明、状態を検証し、サーバー側でIDを発行して保存する。 |
| 更新 | `PUT /api/projects/:id` | 登録済みレコードの名称、説明、状態を更新する。IDは変更しない。 |
| 管理データ一覧 | `GET /api/projects/:id/management-data` | `rootPath`直下の`README.md`から管理データ一覧を読み取り、`status`・`message`・`items`(`title`、`path`、`exists`)を返す。未登録のProjectは404。 |

管理データ一覧は保存せず、リクエストごとに`rootPath`配下から読み取る。読み取る対象は`README.md`だけで、リンク先は存在確認のみ行う。外部URL、絶対パス、`rootPath`の外へ出る相対パスのリンクは一覧に含めない。`status`は`ok`、`root-path-not-set`、`root-path-not-found`、`readme-not-found`、`section-not-found`のいずれかで、`ok`以外は`items`が空になる(HTTPステータスは200)。

Projectレコードは`backend/data/generated/projects.json`へ保存する。同期ファイル操作で、既存の生成データ保存パターンに合わせる。IDは既存IDを調べて発行し、同一IDの上書きは拒否する。

タスク・成果物との関連は各レコードの`projectId`で表す。未設定の既存レコードを初期プロジェクトへ自動で割り当てない。タスクのProject必須化はタスク作成・関連付けを実装するTSK-007で扱う。

## 6. エラー扱い

- 不正なページ値・入力は400と明示的なメッセージを返す。
- 登録・更新対象のProjectがない場合は404。
- JSON読込・保存エラーは既存のエラーハンドラーに渡し、成功形の代替応答を返さない。
- API失敗時、フロントエンドは一覧・詳細にエラーと再試行操作を表示する。空のProjectとして表示しない。

- Project IDのPREFIX・全成果物間一意性を管理する中央採番サービスとの連携。PRJ採番は既存画面・データモデルの例に基づく暫定実装。
- 初期Projectのseedを本番データとして維持するか、初回起動時に別の方法で作成するか。
- Projectに紐づけるQA、課題、Contextの範囲と各管理機能との連携時期。
