# WBS-001 タスク登録簿

## 目的・適用範囲

承認済みの要件定義、既存WBS、開発方針、データモデル設計をもとに、実施可能なタスクと依存関係を整理する。本書内のタスクIDは本登録簿で一意とし、別の管理範囲における採番規則を決定するものではない。

- ID形式：3文字の大文字英字PREFIXと3桁連番（例：TSK-001）。
- 優先度：開発方針のMVPステップ・優先画面を優先しつつ、元WBSのPhaseを維持する。
- 依存：前提作業が完了しないと成果が確定できない場合に限り記載する。
- 日程、工数、担当者：根拠がないため設定しない。
- 状態：TSK-001は本依頼の成果物作成完了により「完了」。その他は元WBSの未完了項目を「未着手」として登録する。

## 依存関係・運用上の確認

- TSK-002で`QAA` PREFIXと全成果物間一意の方針が承認された。既存QAA IDの参照と登録簿の一意性を確認し、正式IDとして扱う。QAA-003〜QAA-007の質問内容は引き続き未回答である。
- TSK-005は優先画面実装（TSK-006～008）の前提設計とする。Phase 0の開発標準・環境整備間は、元資料に必須順序が明記されていないため依存関係を置かない。
- TSK-009 → TSK-010 → TSK-011は、方針確認・設計・採番・関連付けの順序を示す。その他のタスクは、元資料が順序を要求しない限り独立とした。
- QA管理（TSK-008）は識別子方針QA（TSK-002）の記録方法に依存する。TSK-002で未回答の場合、承認済みIDとしての発行を保留する。
- 元WBSに完了チェックのない項目と開発方針の推奨作業を対象にした。完了チェック済みの要件整理、コンテキスト管理設計、ディレクトリ構成設計等は新規タスクとして重複登録していない。

## 前提・未決事項

1. TSK-001の5カテゴリは、管理データ変換ツールの出力定義（Task、Issue、QA、Document、Traceability）に基づく。該当する実データが入力資料にないカテゴリは、内容を創作せず空または未登録理由を記録する。
2. 要件定義書のQA PREFIX例とデータモデル設計書の「QAA」の不一致、および重複禁止範囲は、TSK-002における依頼者の承認により解決した。正式PREFIXは「QAA」、重複禁止範囲は全成果物間である。
3. 要件定義書 3.2、3.3、3.5、3.10、5.2に記載された未決事項は、設計・承認が必要な範囲でタスクの受入条件に引き継いだ。未承認の追加要件は確定仕様として扱わない。
4. 日程、工数、担当者は元資料に裏付けがないため記載しない。優先度は開発方針のMVP順序と画面優先度に基づく相対順位であり、日程の約束ではない。
