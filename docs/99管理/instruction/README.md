# AI実行チケット

WBS-001の未着手タスクTSK-002〜TSK-030を、1ファイル1タスクの実行プロンプトとして整理する。TSK-001は完了済みのため含めない。

## 使い方

1. 対象の`TSK-xxx.md`を1件だけAIに渡す。
2. Router Agentを使用し、同一セッションで複数チケットを混ぜない。
3. 依存タスクの完了を[WBS-001](../WBS-001.md)で確認する。未完了なら実装を始めず、ブロッカーとして報告する。
4. 設計・要件の未決事項は勝手に確定しない。承認や外部操作が必要で権限が確認できない場合は停止し、必要な判断を明示する。
5. 票に記載した完了条件を満たすための範囲だけを変更する。既存の設計、規約、実装パターンを優先し、無関係な変更はしない。
6. Router Agentの作業開始チェック、スコープ定義、レビュー、テスト、トレーサビリティ、Git操作の規則に従う。コミット・マージ・リリースは明示的に依頼された場合だけ行う。
7. 完了時は変更ファイル、受入条件ごとの確認結果、実行した検証と結果、未解決事項を報告する。未実施の確認を完了扱いにしない。

## 情報の優先順位

- タスクの状態・依存・受入条件: [タスク登録簿](../WBS-001.md)
- 計画工数・日程: [ガントチャート](../ガントチャート.md)。計画見積であり、納期の約束ではない。
- 機能要件・設計: 各チケットの「最小コンテキスト」に挙げた原資料。原資料にない仕様は追加しない。

各チケット本文に対象範囲と受入条件を記載する。参照元は必要な該当箇所だけを確認し、無関係な資料を一括で読み込まない。
